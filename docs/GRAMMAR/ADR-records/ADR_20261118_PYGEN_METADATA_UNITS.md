# mcstas-pygen: working METADATA calls and parameter units

## Status

proposed

## Context

`mcstas-pygen`/`mcxtrace-pygen` (`pygen.c.in`) translates an instrument file into McStasScript code. Two parts of that translation did not match McStasScript:

- Component-instance `METADATA` blocks were written as `comp.append_METADATA(type=..., name=..., lines=...)`. McStasScript has no such method, in any release. It has `add_METADATA(name, type, value)` since 0.0.93. The generated `make()` stopped with an `AttributeError`, so no instrument with instance METADATA could pass through pygen.
- Instrument parameters with a unit (`name/"unit"=default`) were translated without it. McStasScript's `add_parameter` accepts `unit=` (checked back to 0.0.84).

Seen with the ESS BIFROST model (generated by niess with mccode-antlr), which has five `nexus_structure_stream_data` METADATA blocks and units on most of its 49 parameters. `mcstas-ess-instr-citool` runs pygen in its model checks, so the model failed them.

## Decision

In `pygen.c.in`:

- Write `comp.add_METADATA(name=..., type=..., value=...)`.
- Add `unit='...'` to `instr.add_parameter(...)` when the parameter has a unit.

No grammar change. mccode-antlr is not affected: it writes no McStasScript code.

## Consequences

Instruments with instance METADATA can be translated by pygen, and the resulting instrument objects keep their METADATA and parameter units.

The generated code needs McStasScript 0.0.93 or newer when the instrument has instance METADATA. Before, it failed with every version.

McStasScript itself still leaves the unit out when it writes an `.instr` file (`write_parameter`). That is a separate McStasScript change.

## Behaviour

- `name/"unit"=default` gives `instr.add_parameter('double', 'name', value=default, unit='unit', ...)`. Parameters without a unit are written as before.
- `METADATA "type" name %{ ... %}` on a component instance gives `comp.add_METADATA(name='name', type='type', value="""...""")`. The content is written as before.
- Tested (macOS arm64, McStasScript 0.0.96): BIFROST from niess v0.17.1 in the `mcstas-ess-instr-citool` layout passes `runci` (model checks and two `%Example` tests) with the new `mcstas-pygen`. It failed the model checks with the old one. `mcxtrace-pygen` was built, not run.
